# 日记对话接入（168增量）

2026-10-13。个人实验原型，沿用原SwiftData真相、现有私有StateBridge、指定设备队列和本地研究记录；未改@Model、未迁移旧历史、没有新增资料服务。本轮接通日记文字，与167事项/单次闹钟共享逻辑入口，权限分开。

## 实际实现

设置→原生操作→Dots对话操作增加两项独立开关：读取日记文字/照片引用，以及确认后新增/修改文字。默认不因已有事项权限开放。29天有界权限、本机先禁用再联网更新、授权版本与固定设备核验保持原规则；撤回可立即禁止本机新的读取或写入，不删除过去的研究证据。

MCP `read_native_journal(commandId,deviceId,query)`提出只读请求。时间窗是entry.date的[start,end)，关键词搜索正文/心情/标签。返回queued只表示服务已保存，设备在线后约20秒轮询读取本地当前保存数据，先保存页结果再回传。用`read_native_command_status`取得实际result；applied在此标为device_reported_read，operationEffect=read_only，不说成写入或用户已看到。读取已获独立设备授权，不要求逐次写入确认；所有文字修改仍必须确认。

页结果带来源bc.native.journal、检索时刻、时区/4点逻辑日、全文revision、matchingCount、hasMore/nextCursor、完整文本与照片引用。图片二进制未读取、CloudKit其他设备同步未知。hasMore时相同范围/游标，以新commandId取下一页；版本或范围改变必须从第一页重读。单条超过32KiB完整读取上限明确报错，不截断后称读完。设备等待、失败和没有日记分别表达；读失败有failed回执，不能返回成功空页。

MCP `submit_native_command(kind=journal,action=create/update)`只按用户明确请求提出正文/心情/标签补丁；create有entryDate，update带原recordId与revision。Dots卡片展示具体改动和创建归属时刻，用户按钮凭据独立于模型；模型不能用“用户同意”授权。单次固定commandId、设备与请求哈希；图片、日期、正文格式、保留字段不会被文字补丁改写；不开放日记代理删除。照片和原文保留，原文可按当前版本另行确认恢复。日记是用户主观轨，观察/习惯/推断不能写成用户感受，不创建持续填写义务。

读取不修改计时、日历或通知；读权限不能执行写入，写权限不包含读取。并发重复读取保留最早原请求，不因内部时间戳变化换身份；保存读结果却回传丢失时重传原页，不悄悄读较新的文字。原请求已接手但本地日志缺失仍未知，不盲目重新接手。读/写均核验授权撤回和版本；完整请求、接收时间、claim、检索内容、结果、错误/重试在本机native-remote-v1.json留存，写入before/proposed继续存在native-actions-v1.json，既有Recorder按nativeCommandIds取得服务器请求与设备页结果。

停止：本机撤回全部对话操作，或单独关闭日记读/写并保存。不把撤权说成取消既有系统闹钟或撤销已保存文字。回滚：先撤权，保留SwiftData、照片与动作/研究原件，再回退App或现有服务版本，不删新增表/原文。旧版不支持journal动作日志类型时保留并报错；优先前向修复。曾保存的旧读页是历史证据，撤权后不把它当成新的实时读取。
