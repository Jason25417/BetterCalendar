# 对话操作的完整回执核对

2026-10-13，0.65.15/172。私有服务仍 v30，不改数据模型、CloudKit、独立权限、本人确认、通知或计时方式。

本次发现两处实际代码缺口：接手接口返回历史完成结果时，原代码在核对当前 commandId/requestHash/attemptId 前就保存为 reported；上传回执后只检查 commandId/requestHash/state，未核对设备、执行身份及完整结果。正常服务会返回正确内容，但错配或损坏的成功响应不能被当作当前请求完成。

现在先核对接手身份，再处理历史结果；上传回执后验证完整请求、设备、能力、执行身份、状态和原结果完全一致，才保存 reported。异常保留 result/原回执/原 attemptId 与可见失败，重启继续上传同一结果，不再执行真实改动。服务已完成且身份一致的历史结果仍可恢复，不强求重新执行。

334 项 Mac 单元测试通过，0 失败/跳过；iOS Simulator 编译通过。新增隔离测试覆盖错设备、错能力、错 attemptId、错结果、另一请求的历史结果以及同身份历史结果恢复。真实 SwiftData 内存库验证只有一次写入，错配回执后重启上传内容不变。这不是生产故障再现或本人操作验收。

发布状态以 [testflight-172.json](evidence/testflight-172.json) 为准；上传和双端 ASC 可安装状态须分别核对，不能以源码 push 代替。用户日用安装、本人表单呈现与确认、真实事项/计时/日记改动、双端屏幕及 AlarmKit 响铃仍未验证。

试用：下一次真正需要的操作继续在 Dots 说明并核对具体表单，之后用原 commandId 查询结果。诊断时可查看本机 native-remote-v1.json/原生导出中的 phase、attemptId、receipt、failures，勿手改或删这些执行档案；reported 只说明服务回执与本机结果匹配，不说明另一端屏幕或本人看见。无需人为制造错配请求。
