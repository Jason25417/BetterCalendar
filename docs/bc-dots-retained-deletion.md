# 可恢复删除：本地实现与旧库升级证据

2026-10-12。本批为未发布代码；目前已安装的 0.65.6/163 不含本功能。

删除从“直接移除数据库行”改为“保留原行、隐藏当前列表”。计划、实际、待办、阶段、日记、照片均保留原内容；执行时段、快照及学习样本继续长期保存。长期区维持现有完成/先放下入口，不新增强制删除。至少保留30天；开发期没有自动永久清除或清空回收站按钮。

## 数据与恢复行为

五个既有模型 PlanBlock、LongTask、LongTaskCheckpoint、JournalEntry、JournalPhoto 各增加四个可空字段：`deletedAt`、`deletionID`、`restoredDeletionID`、`deletionContext`。没有新表或改名。原行身份保持，业务列表过滤删除状态；完整档案仍包含隐藏记录。

恢复确认的是具体删除操作 ID。重复删除不延长同一操作的保留时间；旧操作的恢复不能确认后来另一次删除。并发同身份记录不自动覆盖，提示核对。父事项恢复保留原阶段关系，单独删除过的阶段仍须单独恢复。恢复照片保留二进制数据，并按删除前的位置补回日记引用，不覆盖后来的正文或新照片；毫秒 JSON 的浮点日期误差容许1微秒，匹配出现歧义则拒绝恢复。

恢复日程先恢复日历显示，成功后确认数据库恢复；失败则仍留在回收站。实际恢复先读窗口内现有事件并保留，再追加恢复项，避免覆盖其他设备的日历内容。数据库与 EventKit 不是原子事务；系统写入后若本地保存失败，原行仍保留，提示失败并允许重试，不承诺跨系统原子性。

计划投影和对账识别已有删除标记，防止另一台设备的旧事件回流成新计划。实际日历读取失败会停止对账，不能作为删除证据。原始执行、基线、学习样本和长期事项归属仍保留；累计成就沿用历史累计口径。

设置 → 数据与同步 → 回收站提供刷新与恢复。恢复后通知已有数据刷新链，重新读取当前列表。未做真实双端删除/恢复验收，不将单机测试称为 CloudKit 同步成功。

## 档案版本

新导出使用格式2，包含删除元数据。格式1可明确升级为格式2，在隔离恢复时补空值，原文件不变。未知格式/字段拒绝恢复并保留原档案，避免悄悄丢掉未来字段。开发期内容修订继续要求原值匹配；删除操作身份不允许通过普通内容修订隐式改写。

旧客户端不识别删除标记，还可能沿用物理删除；双方须更新后才验收可恢复删除。新格式2不宣称能由旧客户端读取。原始格式1档案仍在本地。
