# BC 175：双端原生审批与脱敏溯源

2026-10-14。用户本轮明确授权发布服务与双端 TestFlight，并在发布后向 Dots 发送本轮增量测试消息。保留 362af0f 的审批实现；本轮没有改变 CloudKit 模型、权限范围、现有计时或真实事项。

## 产品与行为边界

延续无感、掌控感、代理而不代权：模型提出请求，本人决定，设备执行后回执；不主动追问积压审批，不把未回复当批准。通知仍默认关闭，本人单独启用；点击通知只打开详情。前台App观察不判定纪律、休息或专注，不自动暂停计时。日志与个人活动分开。

## 实际改动

- 新请求默认使用 BC 原生审批，不再调用 Dots 电脑端有布局缺陷的 form。服务提交即返回 awaiting_confirmation 和 approvalUI（指定设备、事项与截止时间、BC顶部待确认入口），无凭据、无自动执行。手机与Mac都提供原生列表/详情和固定底部同意/拒绝。只有指定执行设备可审批，不扩大为跨设备代批。
- 旧 form 保留；已有回传继续校验原 commandId、hash、challenge、grantRevision、期限。仅显式配置 BC_CONFIRMATION_CHANNEL=chat_form 才对新请求使用宿主表单。此配置不修改旧请求身份或复活旧请求。
- 继承新审批可配置默认24h（BC_APPROVAL_TTL_SECONDS），相同决定幂等、相反决定返回409及真实状态；未执行前核对本机授权及内容版本。服务接受、设备接手、设备已应用分别呈现。
- 补齐 callbackTraceId、字段名/类型/缺失、绑定失败阶段、原始/有效状态、共享决定来源与解析得到的取消分类。host_cancel、host_decline、host_accept_unchecked 有不同分类；来源只证明认证传输，真人手势/取消原因仍未知。字段值、元数据内容、凭据和令牌不记录。审批与决定审计同事务，审计持久化失败不宣布完成。
- Mac在既有 mac.activity 权限下增加 appUsage，当天逐App前台累计快照。15s采样、每分钟/切换上传；超过45s采样缺口、休眠和进程重启不补算，系统时钟跳变不归属App。保留coverageStart/unobservedSeconds/omittedSeconds；累计快照替换而不相加。不是Screen Time全量、后台播放/人类专注时长；inputActor未知。已有mac.activity前台名称/标识可见范围不扩大，未访问其他App私有数据。
- iPhone逐App时长本版不接入。再次读取Apple官方approvedWithDataAccess Markdown：需app-and-website-usage entitlement/Apple提供的匹配profile/本人新授权；正式用户设备与Apple Account EU限制仍在，普通TestFlight安装不能保证。这版未加entitlement、未替换签名配置或请求新系统权限。
