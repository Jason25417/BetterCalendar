## 改动与时效

ActivityContent.start/update传入快照staleAt，由iOS系统在App挂起时判断过期；锁屏和展开灵动岛显示「状态待更新 · 按上次状态计时」或「状态待更新 · 上次已暂停」，紧凑/最小岛用刷新图标与相同无障碍说明。保持原计时数字和已知暂停状态，不发通知，不自动暂停/结束/完成事项，不变更MCP执行或授权范围。展示过期是知识边界，不是用户行为错误。

共享计时按最后一次本机成功读取receivedAt+60秒（已有isStale阈值，边界统一>=60）。失败重试不能用投影时间续期，持久缓存重启沿用原时刻；缓存时钟在未来、页未读完或缓存不健康时即时待更新。下一次真实完整读取才刷新时效。屏幕计时仍按服务器中点授时，过期状态按上次运行继续投影，不承诺另一端没有暂停。旧CloudKit只读跟随沿用既有updatedAt+720秒，其他本机原生计时快照保持nil，不增加它的联网依赖。

未修改ActivityAttributes.ContentState字段或SwiftData/CloudKit Model，因此旧系统活动的内容仍可解码；新版App接回后更新staleDate。没有新的资料服务、后台承诺、完整旧历史迁移。现有旧本机active/后台/待恢复状态仍保持自己的记录与展示优先级，不能静默删除或转移历史；这与全场景统一展示仍有边界，真实双端显示需实测。

使用Apple现有原生能力：[staleDate](https://developer.apple.com/documentation/activitykit/activitycontent/staledate)与[Live Activities文档](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)。文档说明系统过期状态及isStale用途，不证明本项目真机屏幕已更新。
